**الخلاصة:** لا ينهار نظام الحضور بالـ QR بسبب متوسط الاستخدام اليومي، بل ينهار الساعة 9:00 صباحاً عندما يمسح 200 طالب شاشة المحاضرة في نفس العشر ثوانٍ. عبر الدمج بين **رموز QR مشفّرة متجددة كل 15 ثانية + تحديد النطاق الجغرافي** مع **Redis** و**قاطع الدائرة Opossum**، خفّضنا زمن الاستجابة بنسبة **98%** (من `94.91ms` إلى `1.53ms`) ورفعنا القدرة إلى **653 طلب/ثانية** باستقرار **99.9%**.

## أكبر مشكلتين في أي نظام حضور بالـ QR

سواء للجامعات أو المعاهد أو الشركات، تفشل الحلول التقليدية بسببين رئيسيين:

1. **التحايل بتصوير الشاشة:** إذا كان الـ QR ثابتاً، يلتقطه طالب ويرسله في مجموعة واتساب لزملائه الغائبين خلال 3 ثوانٍ.
2. **عاصفة الضغط المتزامن (Thundering Herd):** مئات الطلبات تضرب قاعدة البيانات في نفس الثانية بداية المحاضرة، فتستنزف اتصالات PostgreSQL ويتوقف النظام.

## أرقام الأداء الفعلية في الإنتاج (النظام الجامعي)

يعمل النظام في جامعة توكات غازي عثمان باشا لخدمة **أكثر من 2,000 مستخدم** (بمتوسط **~300 عملية تسجيل حضور يومياً**) عبر **6 كليات و13 قسماً و42 مقرراً**:

| المؤشر | قبل التحسين | بعد المعمارية الهجينة | النتيجة |
| :--- | :--- | :--- | :--- |
| **متوسط زمن استجابة الـ API** | `94.91 ms` | **`1.53 ms`** | **تحسن 98%** |
| **القدرة الاستيعابية (Throughput)** | ~10 req/s | **`653 req/s`** | **زيادة +6,100%** |
| **استقرار الخدمة (Uptime)** | توقفات وقت الذروة | **`99.9%`** | صفر أعطال أثناء المحاضرات |
| **استيراد البيانات الضخمة** | إدخال بطيء | **`25,019` سجل في `<1.5s`** | تهيئة آلية للكليات والمقررات |

## المعمارية ثلاثية الركائز

### 1. منع التحايل: QR يتجدد كل 15 ثانية + Geofencing

* يعرض النظام رمز QR موقّعاً رقمياً يتغير تلقائياً **كل 15 ثانية**، مما يُبطل أي صورة مرسلة خارج القاعة فوراً.
* يتم التحقق من الموقع الجغرافي للمستخدم ضمن نطاق **50 إلى 200 متر** من القاعة قبل قبول تسجيل الحضور.

### 2. مسار التحقق الهجين السريع (`JWT + Redis + DB`)

بدلاً من إرهاق PostgreSQL عند كل مسحة في وقت الذروة:

```javascript
// مسار التحقق الهجين لتسجيل الحضور تحت الضغط
async function verifyCheckIn(sessionToken, studentId) {
  // 1. تحقق تشفيري سريع في الذاكرة (<0.2ms)
  const payload = verifySignedQrToken(sessionToken);

  // 2. قراءة فورية من Redis للجلسة ومنع التكرار
  const cachedSession = await redis.get(`session:${payload.sessionId}`);
  if (!cachedSession) {
    throw new Error("انتهت صلاحية الجلسة أو الرمز غير صالح");
  }

  // 3. حفظ آمن في قاعدة البيانات محمي بقاطع الدائرة
  return dbBreaker.fire({ sessionId: payload.sessionId, studentId });
}
```

### 3. الحماية من الانهيار بـ Opossum Circuit Breaker

في حال حدوث ضغط مفاجئ على قاعدة البيانات، يفصل نمط **Circuit Breaker** المسار المتعثر مؤقتاً لحماية Event Loop في Node.js ويمرر التسجيلات عبر مسار احتياطي آمن حتى يستقر الاتصال.

<Callout type="info">
**جودة وأمان الإنتاج:** تمت تغطية مسارات الحضور والجلسات باختبارات تكامل (~85% تغطية في الباك-إند) ودمج فحوصات SAST/DAST في خط CI/CD، مما كشف وأصلح أكثر من 15 ثغرة قبل الإطلاق.
</Callout>

**TL;DR:** A classroom QR attendance system does not fail from average daily traffic: it fails at 09:00 AM when 200 students scan the projector screen in the exact same 10 seconds. By pairing **15-second rotating cryptographic QR tokens + geofencing** with a **Redis hot-path cache** and **Opossum Circuit Breaker** fallback, we cut API latency by **98%** (from `94.91ms` to `1.53ms`) and scaled throughput to **653 req/s** with **99.9% uptime**.

## The Two Hard Problems in QR Attendance Systems

Whether for a university, training center, or corporate office, naive QR attendance implementations fail in two ways:

1. **Cheating via Photo Sharing:** A static QR code gets photographed and sent to absent peers in a group chat within 3 seconds.
2. **Thundering Herd Check-In Spikes:** Hundreds of concurrent HTTP POST requests hit PostgreSQL at once at lecture start, exhausting the DB connection pool and timing out every user.

## The 3-Pillar Architecture That Solves Both Problems

### 1. Anti-Cheat Verification (15s Rotating QR + Geofencing)

* Every classroom session displays a cryptographic token that **rotates every 15 seconds** (signed server-side), making forwarded screenshots useless before they arrive.
* Browser/device geolocation validates the participant is within **50–200 meters** of the classroom coordinates before the check-in is accepted.

### 2. Hybrid Hot-Path Verification Pipeline (`JWT + Redis + DB`)

Instead of hitting PostgreSQL on every token validation during a burst:

```javascript
// Simplified hybrid check-in verification flow
async function verifyCheckIn(sessionToken, studentId) {
  // 1. Fast cryptographic signature check (CPU only, <0.2ms)
  const payload = verifySignedQrToken(sessionToken);

  // 2. O(1) Redis lookup for active session & duplicate-scan guard
  const cachedSession = await redis.get(`session:${payload.sessionId}`);
  if (!cachedSession) {
    throw new Error("Session expired or invalid");
  }

  // 3. Protected persistence behind Opossum Circuit Breaker
  return dbBreaker.fire({ sessionId: payload.sessionId, studentId });
}
```

### 3. Resilience Under Failure (Opossum Circuit Breaker)

If PostgreSQL experiences transient lock contention during a spike, the **Opossum Circuit Breaker** prevents cascading timeouts across the Express.js event loop and routes verified check-ins through an automated temporary fallback buffer until normal DB health resumes.
